LLaMEA Pipeline Refactor - Session Context
Goal of this codebase: Ingest raw log.jsonl files containing Python optimizer classes generated by LLaMEA. The pipeline isolates the code, recursively translates nested loops/blocks into pseudocode via a local LLM, caches semantic translations to enforce consistency, and finally applies fuzzy sequence matching across the classes to calculate a 2D similarity KPI matrix.

📂 Core Architecture & Relevant Paths
1. blade-framework/output-analysis/src/analysis_v3.py
Role: The main orchestrator and CLI entry point.

Features: Dynamically resolves workspace paths. Extracts raw code from log.jsonl and saves as stripped_data/optimisation_N.py. Generates mapping variables.json.
Key Functions: parse_log_jsonl(), recursive_translation(), compute_similarity_metrics().
Execution: uv run python blade-framework/output-analysis/src/analysis_v3.py --force --log-dir <path>
2. blade-framework/output-analysis/src/translator.py
Role: Deepest-first AST recursive parser and LLM interface.

Features: Parses Python code using indentation. Recursively translates the deepest inner blocks first. Once an inner block is translated, replaces it with // :::PSEUDOCODE::: before translating the parent block (preventing LLM hallucination).
Key Classes/Methods: Translator.build_tree(), Translator.query_ollama(model='qwen2.5-coder:14b').
3. blade-framework/output-analysis/src/canonicalizer.py
Role: Caching & Canonicalization.

Features: Provides regex-based whitespace/comment normalization to ensure slight styling differences don't trigger cache misses. Maintains a persistent, cross-class translation dictionary sent as context to the LLM.
Key Classes/Methods: Canonicalizer.canonicalize_code(), get_translation().
4. blade-framework/output-analysis/src/similarity_metrics.py
Role: The KPI evaluation engine.

Features: Parses the Iteration_Final.md markdown files. Assigns fuzzy string matches (thefuzz/Levenshtein) to discrete numeric "Line IDs" (configurable via similarity_threshold=85). Uses difflib.SequenceMatcher to find and count continuous blocks of identical Line IDs across different optimization classes.
Key Classes/Methods: PseudocodeSimilarityAnalyzer.get_sequence_similarity_matrix().
📁 Key Data Directories
Generated outputs are placed dynamically under blade-framework/output-analysis/output/:

stripped_data/: Raw Python source for each class.
pseudocode_classes/: Iterative markdown files (e.g., optimisation_1_Iteration_Final.md).
analysis/kpi_similarity_matrix.csv: The 2D matrix mapping sequence similarity [0-1] between classes.
translation_dict.json: The persistent global dictionary file.
🛠 Next Steps / Debugging Guidance
If translation quality is poor, inspect translator.py's prompt or the normalization logic in canonicalizer.py.
If similarity KPIs are too low/high, adjust the threshold=85 parameter in analysis_v3.py -> compute_similarity_metrics() to tune Levenshtein strictness.
Make sure a local Ollama server is running before executing (http://localhost:11434/api/generate).
